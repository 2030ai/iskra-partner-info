# Кейс 55. Заявки на транспорт → сводный план распределения

**Расчётный потенциал: ≈73,3 часов в год при указанном ниже объёме работы.**

**Пользователь:** административная служба, диспетчер, транспортный координатор.

## Какая работа занимает время

Заявки поступают в сообщениях и документах, а доступность транспорта хранится отдельно. Координатор сверяет время, потребность и ресурс, избегает двойных назначений и запрашивает недостающие сведения.

## Как использовать Искру

Сотрудник передаёт Искре заявки, реестр доступного транспорта, ограничения вместимости и расписания, правила приоритета. Результат работы:

- Общая таблица заявок и доступных ресурсов.
- Предлагаемое распределение с проверкой конфликтов.
- Необеспеченные заявки и причины.
- Проекты запросов уточнений перевозчикам.

Сотрудник проверяет результат и принимает окончательное решение. Диспетчер утверждает назначения и соблюдение транспортных ограничений. Получение заявок из чатов и запись в действующую систему требуют подключения.

**Пример задачи:** «Сведи заявки и предложи распределение транспорта по правилам. Проверь пересечения по времени и двойные назначения, покажи необеспеченные заявки и недостающие данные».

## Расчёт экономии

Плановый расчёт для пилота. Время с Искрой включает подготовку входных данных, проверку и исправления сотрудником; это гипотеза для сопоставимого качества результата, а не подтверждённая экономия конкретного клиента.

| Показатель | Допущение |
| ---| ---: |
| Рабочих дней | 220 |
| Единица работы | один проход распределения |
| Ручная работа на единицу | 30 мин |
| Работа с Искрой, включая проверку | 10 мин |
| Экономия на единицу | **20 мин** |

**220 × (30 − 10) / 60 ≈ 73,3 часов в год.**

Эффект относится к указанному объёму фактически обработанных задач после настройки. При меньшем использовании он уменьшается пропорционально; разовые затраты на запуск вычитаются отдельно.
